# Wording rules of 25 Nov 2026 (owner order) and how they are kept true

This file replaces the vocabulary table in `GLOSSARY.md` (which said engagement and participant). The tests named below fail if the old words come back.

## The rules
1. **A player gives a name.** The word "nickname" is not used anywhere. The check from PR #15 stays: a name is 2 to 20 letters, numbers or spaces, HTML is removed first, and the messages are plain and kind (`cleanPlayerName` in `apps/edge/src/people.ts`).
2. **game and player.** Not engagement, participant, guest or event (the phrase "company events" for the occasion is fine).
3. **co-organizer, never host.** In text a person reads: the second role (key prefix `cbh_`, `kind: "host"` in code) is a **co-organizer**; the third role (`cbc_`, `kind: "cohost"` in code) is an **invite-only co-organizer**. Code values, API role names (`host`, `co-host`) and database columns are not text and are unchanged. "Hosting" (the hosting provider) is a different word and stays.
4. **No ticket.** There are no tickets in this game; there are boards. The setting called `tickets` in the API is a field name and stays.
5. **One payment word set:** the button is **Pay now**; money is **credits**. No checkout, buy now, purchase, top up or recharge in what people read.
6. **Razorpay is never named on a marketing page** (home, about, brochure, organizer guide, pricing, demo, contact, partner, trust, the home page script, llms.txt, the AI manual). It may be named on the payment pages and in the legal documents, where the payer should know.
7. **Never my, mine, your or yours** in user text, except the exact sentence `Copy this link and paste in your AI to work.`
8. **No Hindi consent lines, no tick boxes, no "I agree" checkboxes in anything new** (link to the Terms). The recorded consent boxes K1 to K6 are a legal act tied to Terms version 2026-11-01; they are not changed here (see KNOWLEDGE.md section 7).
9. **Fairness wording only where true in code.** The fairness sentence now reads "No one knows the next roll: not the organizer, not the co-organizer, not even the software." and the privacy sentence says "player information" (`packages/shared/src/lines.ts`). The three rules lines (milestone tie-break, exact finish, tie) are in the same file and are proved by `packages/beacon/test/rules-lines.test.ts`.

## How it is kept true
- `apps/web/test/wording-scan.ts` reads only what a person can read: page text and readable attributes; the quoted strings and template pieces of scripts and Worker source, found with the TypeScript parser (code, comments, regular expressions, SQL and CSS selectors are never read).
- `apps/web/test/wording-set.ts` says which files are read: every page and page script of `apps/web/public` except the legal documents and the recorded consent sentences, every file of `apps/edge/src`, and the engine and shared sources of `packages/beacon/src` and `packages/shared/src`, plus `llms.txt`.
- `apps/web/test/wording-rules.test.ts` fails if "nickname" appears anywhere in the source, the pages, the scripts or the built bundles, and for every other rule it compares each file with its allowance in `apps/web/test/wording-baseline.json`. The file is empty today: **every scanned file holds zero** of the words above. An allowance can only go down, and a file that is not listed has an allowance of 0.
- API names are code, not words, and are left exactly as the API uses them: `tickets`, `/participants`, and the role values `host` and `co-host` inside the AI manuals (`ai-link.ts`, `ai-functions.ts`, `ai-go.ts`, the manifest in `worker.ts`) are exempt there (see `API_NAMES` in `wording-set.ts`); the all-capital `MY` is the country code of Malaysia.
- `packages/beacon/test/rules-lines.test.ts` plays the engine for each rules line; `apps/edge/test/name-check.test.ts` covers the name check and its messages.

## Not covered, on purpose (honest list)
- The legal documents (`terms`, `privacy`, `dpa`, `subprocessors`, `refund-policy`, `partner-terms`, `legal`, `legal-position`) are not edited without the lawyer, and the recorded consent sentences (`consent.js`, `consent-text.json`: "I agree", "my details", the tick boxes K1 to K6) are a legal act tied to Terms version 2026-11-01: the owner decides when they change. The invoice terms in `packages/billing/src` are legal text as well. The owner's own copy `docs/SUITE_RULES.md` still shows the old fairness sentence with "host".
- Older release notes (`apps/edge/src/releases.json`, `CHANGELOG.md`) keep the words of their time; they are history.
- The static `site/` pages (an older copy that is not built into the live site) and the documents under `docs/` are only partly updated.
- Images (the PNG icons, the og card) carry no words that this scan can read; the colour scheme test covers their colours.
- A machine read of the text is not a human read: the "your/my" sentences were rewritten with a parser-based tool (for example "Your game" became "The game"), so a person should read the console and the error guide once for flow.
