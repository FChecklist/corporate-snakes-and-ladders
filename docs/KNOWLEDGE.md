The console-to-game contract is `docs/CONTRACT_V1.md` and `contract/` in corporate-console; the pay contract is `GAME_PAY_CONTRACT.md` (in the console pay-step branch: unknown on the default branch). ## 4a. Owner rules 1.1 as built (version 1.5.0; audit fixes in 1.5.1 to 1.5.5)
- **Switch:** `OWNER_RULES = "1.1"` in `pages/wrangler.toml [vars]`. A game made while it is on stores `rules: "1.1"` in its settings and keeps those rules for life; games made before are untouched. Remove the line to go back for new games. Code: `packages/beacon/src/config.ts` (`validateCfg`, `opts.rules`), `apps/edge/src/people.ts` (`rulesOf`, `verifyOf`, `empCleanFor`, `addPeople`), `apps/edge/src/worker.ts` (create, join, `ownerRules` in `/info` and `/summary`).
- **Invite by ID only:** the game is `verify: "id"`, `employeesOnly: true`, list only, guest invites off. An ID is read one way: every character that is not a letter or digit is dropped, upper case (`A-1101` = `A 1101` = `A/1101` = `A1101`). A roster row keeps the ID only: a name or number sent along is dropped. A join ignores `name` and `phone`. An ID not on the list waits (`POST /api/z/:id/waiting/:wid {decision}`) for the host. IDs are deleted by the purge (20 hours after the game ends; the promise is 24).
- **Everything by itself:** the game starts at the time set (nothing to press); `play: "presence"` ("players throw") is refused under the rules; a roll is `rollFor(game, seat, turn, b_t)` with `b_t` the public beacon value published after the turn closes. The fairness sentence is proved in `packages/beacon/test/fairness-line.test.ts`.
- **Paid only from the console:** `POST /api/console/paid` with `{orderId, gameId}`, headers `x-console-timestamp` (ms, within 5 minutes) and `x-console-signature` (hex HMAC-SHA-256 of `timestamp.body` with `CONSOLE_PAID_SECRET`). Once per order id (`kv cpaid/<orderId>`); the answer for a repeat is `already: true`; an order id used for another game is 409. 404 unless `CONSOLE_PAID_SECRET` and `OWNER_RULES` are both set. Under the rules `/api/checkout`, `/api/payments/test`, `/api/payments/paytest` and the pay-link routes answer 410 `pay-in-console`; `verify` and the Razorpay webhook still finish an order opened before.
- **Guessing IDs: matched, not proven (owner decision, `docs/SUITE_RULES.md`).** An ID is matched, not proven: it is matched to the list and nothing more. Anyone who types a listed ID takes that person's seat, so the game link should go only to the people invited. **A right ID is never counted** and is never refused by a limit (an office shares one network address): do not add a per-address limit on right IDs. Wrong IDs (an ID not on the list) are limited: `wrongIdOverLimit` in `apps/edge/src/worker.ts`, 30 for each game, each network and each 10 minutes (`ID_MISS_PER_10MIN`), one count shared by "Is this you?" (`who`) and join, raised in ONE database step (`INSERT ... ON CONFLICT DO UPDATE ... RETURNING`) so parallel guesses cannot read the same old number. The network is `networkOf(cf-connecting-ip)`: IPv4 as it is, IPv6 by its first 64 bits, no address = one shared bucket `local` (never on the live site). The 31st wrong ID answers 429 `too-many-tries` and is not put on the waiting list. What this does not do: it only slows a guesser; the 429 shows which tries were wrong; an ID that is already seated answers `id-used` and a right ID answers `known:true` without any limit. The counters (`idmiss/<game>/<10 minutes>/<hash of the network>`) hold no ID; `erasePersonal` deletes them and the retention sweep removes old ones. Tests: `apps/edge/test/owner-rules.test.ts` (guessing IDs).
- **Console notice, 1.5.1:** the order id is claimed first and a game is marked only by the notice that won the claim; a game already paid answers `already` and uses no order id; a `CONSOLE_PAID_SECRET` shorter than 32 characters counts as no secret (404). The older routes `verify` and the Razorpay webhook still finish an order that was opened before the deploy, so "paid only from the console" holds for every order opened after it.
- **Console notice, 1.5.2:** the order id row (`kv cpaid/<orderId>`) and the game's `pack` are written in ONE `db.batch` (all or nothing); the game is marked only if the row names this game (`json_extract(v,'$.gameId')`). A failed batch answers 503 `try-again` and removes its own row, so the console can repeat the same notice. A repeat answers `already` only when `pack > 0`; a row left for an unpaid game is finished by the repeat. Tests: `apps/edge/test/owner-rules.test.ts` section 1.5.2 (the test database now runs a batch as one transaction, like D1).
- **Winners are kept 365 days, the rest of a winner's request is not (owner rule; 1.5.4 put right what 1.5.2 and 1.5.3 had reversed).** A winner's name, mobile number and employee ID (`prize.pii`, `prize.orig`, `prize.trail`) stay for 365 days with the winners record (seat, prize, round, time, given). In the security log (`apps/edge/src/audit.ts`) the winner's `/confirm` row is split with no switch: `winnerPart` keeps `{winner: {seat, name, phone}, method, path, status, server_utc}` in the row's core (365 days; `loadRows` shows it as `details.winner` after the rest is shredded), and everything else (network address, browser, phone id, participant id, other fields) goes to `audit_pii`, sealed under the game's own key, destroyed by `shredParticipantAudit` at 24 hours. Nothing depends on `OWNER_RULES`, so a deploy or a rollback cannot make the e-mail untrue. A participant call for a game id that is not a game writes no row and no key; a caller's `x-request-id` is never copied (`corr` is `cf-ray`); the country column of a participant row is empty. Rows written by an older version keep what they hold until 365 days (rows are chained). The report, e-mails, `index.html`, `llms.txt` and `trust-page.ts` say this; the consent sentence and the Terms table already did. Tests: `apps/edge/test/owner-rules.test.ts` section "1.5.4".
- **A reported win is checked against the public game (1.5.4, `apps/edge/src/verifywin.ts`, called by `acceptVotes` in `winners.ts`).** A phone's report (`POST /api/z/:id/vote`) is counted only when: its turn has happened (`betaRoundOf` with the game's pauses and breaks, `scheduleOf` in `lifecycle.ts`); every named seat exists; the prizes that need the whole game wait for the end (`endBoundMs` or the phones' `over`); and the named seat really got there: the server fetches the beacon's numbers from `api.drand.sh` (first two mirrors, 20 per call, kept in `kv bcn/<game>/<round>`), plays that seat's board (`boardOf`, `rollFor`, `runFrom`) and compares (milestone turn, home turn, a ladder, a snake escape; team = one whole team by `teamsOf`; lucky draw = `luckyWinners` again). Home places and milestone lines must agree with lines already settled. A report not yet true gets 409 `not-yet` and the phone resends; a false one is dropped (`refused` in the answer). A checked report is remembered in `kv vok/<game>/<digest>`. Both kv prefixes are removed by `erasePersonal`. **Limit in 1.5.4 (lifted for four prizes in 1.5.5, next bullet):** the server proved the named seat got there, not that nobody got there first; the console's override stays the final word. Milestone and finish prizes still work this way. The beacon's signature is not checked on the server (the phones check it). Tests: `apps/edge/test/vote-check.test.ts`; test helpers `apps/edge/test/beacon.ts` (stand-in for the beacon servers) and `truth.ts` (the true result of a game, as a phone works it out); any test that needs a winner must report a true one (`settleTrue`).
- **The four whole-game prizes are settled only by a server replay (1.5.5, `apps/edge/src/replay.ts`, used by `verifywin.ts`).** Biggest climb, biggest comeback, never missed and the team prize are accepted only when they equal what the server works out by playing every seat of the game from the public beacon numbers and the seat list, using `settleRace` (the function the phones use). A seat that climbed a little, or a whole team that is not the true winner, is refused. The replay runs in parts of `REPLAY_SEATS_PER_CALL` seats (default 100), each stored as seat numbers and squares only in `kv tru/<game>/<end turn>/<part>`; until every part exists the phones get 409 `not-yet` and resend. It also checks that the game really ended on the turn named. Table games use `playTable`/`settleTable`. Presence-mode games (older, no stored throws) refuse these four prizes and the organizer gives them from the console. `tru/` is removed by `erasePersonal`. **Plan fact:** `pages/wrangler.toml` states the paid Workers plan (owner, 2026-10-27), which is why a full replay is allowed; `apps/edge/wrangler.toml` is the unused free-plan design. **Wording:** the console correction (`override`, a prize given to another card that claimed it, logged with who and when) is real, so no page, e-mail or fact says a winner can never be changed; the legal terms still do and are the owner's to decide. Tests: `apps/edge/test/verify-end-prizes.test.ts` (helper `truth.ts` now also returns the runs).
- **Smaller 1.5.4 fixes:** `sameSecret` (constant-time compare) for the platform and scheduler keys; `joinOverLimit` counts by `networkOf` in one statement; `POST /api/z/:id/myprizes` takes the phone's proof in the body (GET stays for older pages); a failing `reportStep` no longer blocks `erasePersonal` in `lifecycleTick`.
- **Wording:** organizer and host screens say you (test `apps/web/test/owner-rules-lines.test.ts`). The privacy line and the fairness sentence are in `packages/shared/src/lines.ts` and on the pages word for word. Prices carry the rupee sign (the PDF report still prints `Rs` because its font has no rupee glyph).
